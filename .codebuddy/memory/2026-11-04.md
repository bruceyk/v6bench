## 解释 `v6bench/kathara/dns/etc/bindfiles/named.conf.options`
- 结论要点（供后续修改时参考）：
  - `listen-on-v6 { any; }` 是必需项：BIND 9.16+ 默认只听 `::1`，lab 里 v6-only 客户端的 resolver 是 `2001:db8:1::53`（IPv6），不放开就查不到 DNS。
  - `dns64 64:ff9b::/96 { clients { any; } }` 与 nat64 节点 Jool 的 `pool6 64:ff9b::/96` + gateway 的 `ip -6 route add 64:ff9b::/96 via 2001:db8:1::64` 三者配套，构成 draft 场景 #4 的闭环。
  - 缺陷：`clients { any; }` 让 DNS64 对双栈客户端也生效，会污染 draft 场景 #1（Dual→IPv4-only），见 `doc/v6bench_analysis.md` 的 D-3。
  - `dnssec-validation false` + 不配 forwarders → named 自行递归解析外网域名，依赖 host IPv4 出网；`test_runner.sh` 等 DNS 用的正是外网域名（D-7）。
